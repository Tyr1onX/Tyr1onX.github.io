课刻 · Windows 桌面课表

让一天在桌面上缓慢流动。

Core capabilities

功能不是列表，而是四个完整的使用闭环。

课刻目前最重要的价值，不是把所有课程一次性摆满屏幕，而是把导入、理解、编辑和长期使用串成一套本地桌面体验。

01

此刻优先

桌面组件根据日期、教学周和当前时间判断正在上课、下一节课、今日结束或当天无课，让用户先看到现在最需要的信息。

02

从 Excel 到可编辑课表

学校导出的 .xlsx 文件只在本机解析。导入前先检查课程、星期、节次、周次、地点和教师，再创建一张独立课表。

03

多课表与课程管理

每次导入都生成独立课表，可切换、激活、编辑和删除；课程也能手动新增、修改，并支持多个时间段与单双周。

04

真正的桌面应用行为

系统托盘、开机启动、窗口位置恢复、单实例、DPI 与多显示器适配，共同保证它不是一个悬浮网页，而是能长期留在桌面的工具。

Design decisions

项目里真正重要的，是这些取舍。

功能可以继续增加，但课刻必须始终回答同一个问题：怎样让课程、时间和桌面之间的关系更自然，而不是把复杂度重新交给用户。

01

为什么不是固定表格

完整课表适合规划，桌面组件更适合提醒。主窗口只展示日期、教学周、当前课程和后续课程，七日总览被放进独立设置窗口。

02

为什么选择 Tauri

项目需要透明无边框窗口、系统托盘、本地文件解析和安装包，同时又希望保持较轻的桌面体积。Tauri 让界面与 Rust 本地能力在同一个项目中协作。

03

为什么坚持本地优先

课表文件可能包含姓名、教师和教室信息。Excel 解析、课表与设置都留在应用专属目录，不通过服务器换取便利。

04

为什么把稳定性放在动效之前

桌面窗口必须在 Windows 缩放、多显示器和不同课程数量下保持稳定。视觉与时间流动动效只有在不破坏阅读、输入和窗口行为时才会保留。

Implementation

一套正在运行的桌面结构，也保留真实边界。

这里不把限制包装成“未来愿景”。已完成的能力、窗口约束和暂时没有实现的功能都应该被清楚地写出来。

窗口与数据

  • 主组件固定 392px 逻辑宽度，高度按内容在 160–740px 之间调整。
  • 透明、无边框、隐藏任务栏，并以 always-on-bottom 方式留在桌面。
  • 设置窗口默认 1180×760，可调整大小，最低 960×640。
  • 课表、设置、多课表索引和备份均保存在本地应用目录。

当前限制

  • 目前仅支持 Windows。
  • 正式导入入口仍以 .xlsx 为主，不同教务系统可能需要额外适配。
  • 暂不支持课程通知、云同步和自动更新。
  • 安装包尚未进行商业代码签名，Windows 可能显示来源未知提示。

Trajectory

它不是突然完成的，而是一段连续收敛的过程。

课刻的迭代不是简单累加功能。每一阶段都在把一个浏览器原型，逐步变成可以安装、导入、编辑和长期使用的桌面产品。

起点

从桌面视觉原型开始

先验证“当前课程优先”的信息结构，以及不同桌面背景、课程数量和时间状态下的可读性。

桌面化

建立 Tauri 窗口与系统行为

加入透明无边框窗口、系统托盘、单实例、位置恢复、开机启动和 Windows 安装包。

数据化

让 Excel 成为真正的数据入口

本机解析 .xlsx，增加导入预览、错误检查和隐私说明，让用户在创建课表前先看见系统理解了什么。

管理化

从单课表扩展到多课表与课程编辑

加入课表切换、激活、删除，课程新增与修改，以及学期周数、作息时间和旧数据迁移。

统一名称、发布与使用路径
